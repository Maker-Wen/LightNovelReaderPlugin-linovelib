## 维护约定

- 在规则所在位置说明关键决策的理由及适用边界。调整行为时同步更新对应文档，其他文档通过链接引用该处。
- 源码和测试用于核实实现；文档用于保存难以从代码直接看出的意图与约束。发现冲突时先核对当前代码、测试和相关提交，再修正说明。
- 执行结果统一记录在开发文档，注明日期、代码、实际包和宿主环境。源码变化后重新判断旧结果的适用范围，分别报告本地测试、设备验收和发行状态。
- 文档链接使用相对路径，并指向版本控制内的文件。原始日志、截图、数据库及实验工具留作本地证据，现行文档保留必要结论和基线。
- 历史材料只在追溯具体决策时按相关提交查阅；仍影响当前维护的理由应直接写入现行文档，接手工作从本索引开始。
