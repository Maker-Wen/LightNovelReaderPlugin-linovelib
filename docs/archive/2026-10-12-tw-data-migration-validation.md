# Linovelib TW 本地迁入实现与验证

> 历史迁入验收，保留每次构建、样本和故障场景的实际结果，不代表之后所有改动都重复跑过这些设备用例。现行规则见 [TW 数据迁入](../tw-data-migration.md)，其他验证见 [文档索引](../README.md)。本机临时证据路径不保证长期存在。

日期：2026-10-12。保持 API 3、当前源 ID 和 `.net` 入口；规则见 [实现规范](../tw-data-migration.md)。

## 实现

普通冷启动检测 TW 数据并弹窗确认，点击后显示不可取消的本地进度。资料、整本书目录、正文及图片引用按当前源优先、TW 补充合并，不转换文字、不强制联网。书架、定位、阅读历史与时长按规范合并，后续沿宿主正常读取和刷新流程更新。

`MigrationPlanner` 负责纯数据校验和合并；`Api3HostAdapter` 使用注入 DAO 所属的真实 Room/SQLite 连接，把业务数据、源选择与完成凭据 `linovelib.migration.tw.v1.receipt` 放在同一事务中。事务内重新读取活动数据并核对来源快照，提交失败整体回滚，完成凭据防止再次累计。成功后要求重新打开阅读器，避免旧会话覆盖结果。

官方 ZIP `data` / 裸 CBOR 快照由插件读取，不增加运行时依赖；单文件及解包数据限 64 MiB，超限停止预检。宿主按实际 API、对象身份、schema 17 和表结构校验，不维护版本或 APK 哈希允许列表，也不接管后台任务。旧封面域名兼容已移除，通用 URL 解析、图片请求头与共享正文图片缓存保留。

## 验证覆盖

- 126 项 JVM 测试此前通过，覆盖合并规则、统计边界、章节 ID、官方快照夹具、启动准入和最近阅读顺序。Debug、Release 构建及内置 ABI 检查通过，Release lint 通过；另比对正式宿主 DEX 中的实际迁入接口与日期时间引用。
- 官方 API 3 的 `1.2.1`、`1.2.2`、`1.2.2a`、`1.2.3`、`1.2.3a`、`1.2.3b`、`1.2.3c` 共七版，数据库与启动约定一致。合成数据设备验证共 63 个场景：两种活动源、重复启动、SQL ABORT、实际写事务中强退、从中断状态重试、旧正文离线阅读和正常切源后的凭据保存恢复。
- 七版矩阵使用 Debug 构建 `b478d9af…`；后续修正最近阅读的保存顺序，并删除取消的繁体缓存提示。最终 Debug SHA-256 为 `6c634c0066debd8f9113dfed370e3801543c376ce8424432bdf0ac24a333f83a`，未把历史矩阵记作最终包重测。
- 较大真实内容样本使用正式 `1.2.3c`、上游 TW `v1.1.2` 及独立 Android API 37 模拟器。资料、正文和阅读记录均通过正常使用产生，没有手工填充业务数据，也没有使用个人历史备份。

最终包在两种活动源下均符合独立预期：当前资料及整份目录优先，正文冲突保留当前源，记录相加，最近阅读顺序正确。1036 个正文引用的本地文件全部保持内容哈希，来源快照不变。正常合并及重复启动、凭据写入时 SQL ABORT、实际写事务强退、同一中断状态重试及再次启动均通过；数据库完整性正常，没有半批数据或重复累计。强退依据是有效未提交 WAL 帧，未把 WAL 文件大小当成有效写入量。

当前源 → Wenku8 → 当前源后，凭据和源内业务数据恢复，无重复迁入。实际断网阅读 TW 独有书籍可显示繁体正文与本地插图。较小真实样本使用 `a9fc2be1…` 构建，还验证了联网正常获取后的简体正文写回；默认滚动模式需要退出再进入同章才能看到更新，未访问内容保留原缓存。统计列表的书名和封面正常显示；时长按数据库字段核验，宿主主页存在既有单位格式化问题。样本未覆盖旧封面域名失效，亦未覆盖真实同小时超过 60 分钟的封顶分支，该统计边界由合成数据与单元测试覆盖。

较大样本点击至观察到提交日志约 0.64～0.73 秒，首次采到完成界面约 2.6 秒，包含 ADB 观察开销；RSS 样本最高约 293～306 MiB。这些观察不代表精确事务耗时、堆分配峰值或低内存设备表现。正常合并较快，未采到中间逐书进度；故障暂停场景显示保存阶段进度且无取消入口。
