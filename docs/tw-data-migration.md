# TW 数据迁入

[文档索引](README.md) · [当前架构](architecture.md) · [最近验收基线](development.md#最近验收基线)

本文说明当前已实现的迁入规则，包括可恢复坏数据的处理和一次性迁入保护。历史双站切换方案不再适用。

将上游 TW（`282781674`）的本地数据一次性合并到当前 Linovelib（`-1488977864`），只升级插件，兼容现有官方 API 3 宿主。合并不要求联网，不做繁转简；继续使用 `.net`，保持一个可见的 Linovelib，不增加设置页。

坚持插件内、API 3 的边界，是为了让现有官方宿主直接接纳迁入结果；只保留一个可见源，是为了让合并后的阅读状态继续累积在同一处。迁入不扩展为双站运行或宿主升级方案。

## 使用流程

1. 插件装载时检查宿主、活动源与候选数据，普通冷启动首次恢复主页面时同步显示确认弹窗。
2. 选择“暂不同步”保留原数据；选择“开始同步”进入不可取消的本地合并进度。
3. 提交成功后提示“已迁入可恢复的数据，请重新打开阅读器”。完成凭据阻止重复累计，不提供增量同步；完成提示不代表所有损坏记录都已恢复。

当前功能包含在源码中；实际安装包是否包含它，以对应发行说明和代码基线为准。

## 合并规则

| 数据 | 合并规则 |
| --- | --- |
| 书籍资料与封面 | 当前源已有有效资料时整条保留，否则采用 TW 资料；封面引用原样保留，不做旧域名兼容或补下载 |
| 卷与章节目录 | 当前源已有含章节的有效目录时整本保留，否则采用 TW 目录；卷、章节和顺序整体选择，不混拼 |
| 正文与图片 | 按归一后的章节 ID 合并，同章当前源有效非空正文优先；保留选中正文的图片与前后章引用，不丢弃未被选定目录引用的正文，不清空共享图片文件 |
| 书架 | 名称精确匹配；同名架保留当前成员顺序并追加 TW 独有成员，按书籍 ID 去重。架 ID 冲突统一映射正反向引用；已有架偏好保留，新架采用默认值 |
| 最近阅读 | 按书籍 ID 合并，按最后阅读时间从早到晚保存，供宿主反转显示；仅有资料或缓存不自动加入书架、最近阅读或生成历史 |
| 定位与章节进度 | 当前非空定位优先，否则补 TW 定位；当前进度同键当前源优先，历史最大进度同键取大。缺少目录或目录缺章不清空定位及进度映射 |
| 整本书进度 | 有阅读数据和目录时，按 `maxChapterReadingProgressMap.values.sum() / 目录章节总数` 计算并限制在 `0..1`；无目录时保留当前已有合法整体进度，仅有 TW 记录则采用 TW 值 |
| 逐书阅读记录 | 按 `(bookId, date)` 合并：次数与秒数分别相加，完成和收藏标记取 OR，已知的首次与末次时间分别取早、晚；TW 缺失或无效的时刻不覆盖当前已知时刻。缺少资料的历史和只有日期统计的数据也保留 |
| 用户累计时长 | 单侧合法累计时长保留原值；两侧均有记录时累计秒数相加，`-1` 求和时视为零，两侧都是 `-1` 才保留 `-1`。最后阅读时间取晚 |
| 每小时统计 | 按日期逐小时相加，每小时最高 60 分钟；逐书秒数、用户累计秒数、小时分钟分别合并，不互相推算 |
| 缓存与导出记录 | 已有 `CACHE` 完成记录按 `(type, bookId)` 去重，仅在最终目录含章节且每章均有有效正文时保留；正文不足仍保留部分缓存，不新增下载历史或恢复任务。当前源导出记录保留，TW 导出记录不迁入 |
| 其他数据 | 当前源偏好、搜索历史、格式规则及全局设置保留；不复制 TW 偏好或影响其他源 |

已有资料和缓存通过正常详情、阅读、预加载或缓存任务更新，获取失败保留旧内容；快捷目录可能只读取本地缓存。未访问的内容可以长期保留繁体，不保证当前阅读页立即替换正文或点击后立即恢复封面。

书籍按网站 ID 匹配，章节支持裸网站 ID、`linovelib-v2:` 和 `linovelib-v3:`，统一归一到 `linovelib-v3:`。目录、正文、导航、定位及进度使用同一规则。同源章节资料与正文先选有效内容，再按 v3、v2、裸 ID 的顺序选择；当前章节进度按该顺序选择，最大进度取大。

次数、逐书秒数和累计秒数按字段独立合并。两侧合法值相加超过 `Int.MAX_VALUE` 时，该字段保留当前值，其他安全字段仍可合并。小时统计只接受单源每小时 `0..60` 的合法编码，合法值相加后限制为 60；损坏的 TW 小时记录跳过，不把坏编码修成有效统计。

### 损坏数据的恢复边界

TW 输入尽量保留可恢复部分：无效书籍 ID 的记录、重复个人数据主键和无法安全解释的记录跳过；阅读定位、进度、时间及统计字段可独立恢复，缺失字段只使用安全默认值。有限但越界的 TW 进度限制到 `0..1`，无效章节进度条目跳过。TW 书架和已知列表过滤无效成员，并根据有效书架成员重建反向引用。

书籍资料、目录和正文属于可重新获取的缓存。无效缓存可被舍弃或由另一侧有效内容替代；某本书的卷顺序、章节引用或所有权冲突会使该本目录整体退出选择，其他书籍及独立正文仍可保留。已知正文组件只保留宿主可读取的字段；未知组件 ID 原样交给宿主处理，不承诺能够正常显示。

当前源无法解释的个人数据原样保留，并保护对应主键，阻止 TW 同键数据覆盖或累计；无法确认主键时保护该表，书架还保护同名冲突。个人历史无法重新下载，解析失败不证明原值无用，因此不能用猜测或默认值“修复”当前历史。这些保留行在活动当前源中使用原始 SQL 值写回，不用解析失败的占位值替换原值。非活动当前源快照必须能完整装载，无法完整解码时停止迁入。来源身份、快照归属、宿主存储结构和事务准入仍须通过校验，不能凭默认值推断。

没有可恢复的 TW 内容时不保存结果、不写完成凭据，也不切换数据源。空默认书架、源选择或普通偏好、空阅读记录，以及缺少完整缓存支撑的完成标记，都不足以完成迁入。排除受保护的 TW 记录后，若不再有任何可恢复内容，也按无数据结束；已有相同有效内容则仍可完成一次性迁入。

## 关键设计

### 权威输入与宿主适配

每源只取一份输入：活动源取真实数据库，非活动源取 `local_data/<sourceId>` 快照；归属依据持久化选中源。数据库与该源旧快照可能是同一份历史的不同时间副本，两份并存不代表可以相加；运行时空 provider 的 `-1` 也不能证明归属。活动源为 TW 或当前 Linovelib 时才提交，其他源等待正常切源。

快照支持官方 ZIP `data` / 裸 CBOR，文件及解包数据限 64 MiB。非活动 TW 优先读取 `local_data/282781674`：能解码且身份与归属有效时只使用它，不再比较或合并 `-1`，也不因其缺少可恢复内容而改用 `-1`。只有标准 TW 文件不存在或无法读取时，才尝试 `local_data/-1`；该文件顶层 ID 必须为 `-1`，内部唯一且类型合法的持久化选中源必须明确为 TW。固定优先级避免重复累计同一份历史，明确归属避免错并其他源。两份文件不要求个人数据指纹一致，指纹用于完成凭据记录，不用于拼接快照。

宿主私有访问集中在适配器：核对官方包、实际 API 3、注入 DAO 所属的真实 Room/SQLite 连接、实际 `LocalDataManager`、数据库路径、schema 17 和表列结构。版本号或 APK 哈希本身不能证明连接与存储契约一致，因此按实际契约准入，不维护版本号或 APK 哈希允许列表，不使用逐表非事务导入。

### 启动与交互

普通冷启动首次恢复主页面时确认，等待默认书架初始化完成并核验冲突任务后开始；不接管宿主后台任务，仅允许已核对处于等待状态的 `checkUpdate` 周期工作。恢复旧页面、热加载和外部入口不启动迁入。这样可以在已确认的启动状态中合并，避免与宿主初始化或后台工作竞争。

标题为“合并 TW 数据”，按钮为“暂不同步”和“开始同步”。开始后同步显示不可取消的本地进度，阻止阅读器内的普通触摸操作。页面重建沿用同一次尝试，最多等待初始化 30 秒且不因重建延期。写事务之前和标记成功之前，都须确认本次进度弹窗已在 resumed 的实际页面显示，且该页面仍通过初始化与任务检查。

页面失去前台、弹窗消失或插件卸载会撤销准入，但在途工作仍先结算存储结果；事务内不等待 UI，也不把已提交结果随页面一起丢弃。显式前台渲染失败会永久撤销本次冷启动资格。会话与绑定实现见 [当前架构](architecture.md)。

读取、合并、保存和完成按实际工作显示；处理完全部书籍仍处于保存阶段。只有已确认未开始写入或正常回滚、错误可恢复且冷启动会话有效时，才显示手动“重试”。尝试中确认没有可恢复 TW 数据、来源变化、非活动目标已有可信凭据或凭据不可信时，按原因显示“本次未同步”，本次不写入，关闭提示后可继续使用阅读器。可能已提交却无法核实时显示“保存结果待确认”，仅提供关闭阅读器；凭据查询失败不等于凭据不存在。

现有生命周期与弹窗绑定不观察同一个主页面收到的新 Intent，也不证明窗口输入独占。相关验证边界见 [已知验证边界](development.md#已知验证边界)。

### 原子提交与重复保护

1. 本地读取、校验并准备合并计划，提交前原数据不变。
2. 在宿主真实 Room 的同一 SQLite 连接开启事务，重新核对选中源、来源快照及完成凭据，读取最新活动数据再合并。
3. 同一事务写入完整业务结果、当前源选择和完成凭据；标记成功前再次检查准入，正常回滚时整批恢复，不替换数据库或来源快照文件。
4. 提交成功后结束旧会话，提示重新打开阅读器加载新数据；提交后的显示失败只提示重新打开，不重新累计。

采用一次性迁入，是因为阅读次数与时长需要相加，重复执行会继续累计；来源之后变化也不能据此识别可安全追加的增量。业务结果、源选择和完成凭据必须同事务提交，否则闪退可能留下“已累计但没有凭据”的状态，下次启动便会重复合并。

Adapter 区分未开始、正常回滚、提交正常返回和事务退出不确定；只有事务退出后才能核对完成凭据。结果不确定时，可信当前目标凭据可以确认完成，否则要求重启。未查到凭据不能证明不确定退出没有写入，所以即使独立查询未发现凭据，也不能在原会话重试。非活动目标快照已有可信凭据只表示不应再合并，不自动切源，也不显示本次完成。

完成凭据为目标源内的 `linovelib.migration.tw.v1.receipt`，通过实际 `LocalDataManager` 登记，随目标源切换、导出、清除和恢复。凭据只有类型、迁入标识、规则版本、来源与目标 ID、个人数据指纹及提交 ID 均符合约定时才可信。重复、损坏或字段不符的凭据按“不可信”处理：它可能来自已经完成的迁入，不能当作不存在再累计；本次跳过迁入，保留正常阅读能力。装载检查发现活动当前源已有可信或不可信凭据时均不再启动迁入。

事务未提交时闪退保留原状态；提交后即使尚未显示完成，数据与凭据也一起生效。已有可信凭据时不再累计，旧 TW 数据变化不作为新批次；不支持增量同步或逐书补迁。
