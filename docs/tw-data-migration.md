# TW 数据迁入

[文档索引](README.md) · [当前架构](architecture.md) · [迁入验证记录](archive/2026-10-12-tw-data-migration-validation.md)

本文为已实现的迁入规则，最初于 2026-10-11 编写，整理时已对照当前代码。历史双站切换方案不再适用。

将上游 TW（`282781674`）的本地数据一次性合并到当前 Linovelib（`-1488977864`），只升级插件，兼容现有官方 API 3 宿主。合并不要求联网，不做繁转简；继续使用 `.net`，保持一个可见的 Linovelib，不增加设置页。

## 使用流程

1. 插件在普通冷启动恢复主页面时检测本地 TW 数据；满足宿主、活动源和任务准入条件后显示确认弹窗。
2. 选择“暂不同步”保留原数据；选择“开始同步”进入不可取消的本地合并进度。
3. 提交成功后按提示重新打开阅读器。完成凭据阻止重复累计，不提供增量同步。

当前功能包含在源码中；实际安装包是否包含它，以对应发行说明和代码基线为准。

## 合并规则

| 数据 | 合并规则 |
| --- | --- |
| 书籍资料与封面 | 当前源已有有效资料时整条保留，否则采用 TW 资料；封面引用原样保留，不做旧域名兼容或补下载 |
| 卷与章节目录 | 当前源已有含章节的有效目录时整本保留，否则采用 TW 目录；卷、章节和顺序整体选择，不混拼 |
| 正文与图片 | 按归一后的章节 ID 合并，同章当前源有效非空正文优先；保留选中正文的图片与前后章引用，不丢弃未被选定目录引用的正文，不清空共享图片文件 |
| 书架 | 名称精确匹配；同名架保留当前成员顺序并追加 TW 独有成员，按书籍 ID 去重。架 ID 冲突统一映射正反向引用；已有架偏好保留，新架采用默认值 |
| 最近阅读 | 按书籍 ID 合并，按最后阅读时间从早到晚保存，供宿主反转显示；仅有资料或缓存不自动加入书架、最近阅读或生成历史 |
| 定位与章节进度 | 当前非空定位优先，否则补 TW 定位；当前进度同键当前源优先，历史最大进度同键取大。缺少目录或目录缺章不清空定位及进度映射 |
| 整本书进度 | 有阅读数据和目录时，按 `maxChapterReadingProgressMap.values.sum() / 目录章节总数` 计算并限制在 `0..1`；无目录时保留当前已有合法整体进度，仅有 TW 记录则采用 TW 值 |
| 逐书阅读记录 | 按 `(bookId, date)` 合并：次数与秒数相加，完成和收藏标记取 OR，首次与末次时间分别取早、晚；缺少资料的历史和只有日期统计的数据也保留 |
| 用户累计时长 | 单侧累计时长保留原值；两侧均有记录时累计秒数相加，`-1` 求和时视为零，两侧都是 `-1` 才保留 `-1`。最后阅读时间取晚 |
| 每小时统计 | 按日期逐小时相加，每小时最高 60 分钟；逐书秒数、用户累计秒数、小时分钟分别合并，不互相推算 |
| 缓存与导出记录 | 已有 `CACHE` 完成记录按 `(type, bookId)` 去重，仅在最终目录含章节且每章均有有效正文时保留；正文不足仍保留部分缓存，不新增下载历史或恢复任务。当前源导出记录保留，TW 导出记录不迁入 |
| 其他数据 | 当前源偏好、搜索历史、格式规则及全局设置保留；不复制 TW 偏好或影响其他源 |

已有资料和缓存通过正常详情、阅读、预加载或缓存任务更新，获取失败保留旧内容；快捷目录可能只读取本地缓存。未访问的内容可以长期保留繁体，不保证当前阅读页立即替换正文或点击后立即恢复封面。

书籍按网站 ID 匹配，章节使用已验证格式归一到 `linovelib-v3:`，目录、正文、导航、定位及进度使用同一规则。同源别名冲突按当前格式、已支持旧版本、裸网站 ID 的顺序选择，最大进度取大。未知 ID、损坏结构、非法数值或溢出停止预检，原数据不变；60 分钟上限只用于合法小时值相加。

## 关键设计

### 权威输入与宿主适配

每源只取一份输入：活动源取真实数据库，非活动源取 `local_data/<sourceId>` 快照；归属依据持久化选中源，不能把数据库与该源旧快照重复相加，也不能用运行时空 provider 的 `-1` 推断归属。活动源为 TW 或当前 Linovelib 时才提交，其他源等待正常切源。

快照支持官方 ZIP `data` / 裸 CBOR，文件及解包数据限 64 MiB。`-1` 快照仅在文件名和顶层 ID 均为 `-1`、内部唯一选中源明确为 TW 时接受；与 TW 快照并存时须有相同个人数据指纹才能去重，归属或重复关系不明则停止。

宿主私有访问集中在适配器：核对官方包、实际 API 3、注入 DAO 所属的真实 Room/SQLite 连接、实际 `LocalDataManager`、数据库路径、schema 17 和表列结构。不维护版本号或 APK 哈希允许列表，不使用逐表非事务导入。

### 启动与交互

普通冷启动首次恢复主页面时确认，等待默认书架初始化完成并核验冲突任务后开始；不接管宿主后台任务，仅允许已核对处于等待状态的 `checkUpdate` 周期工作。恢复旧页面、热加载和外部入口不启动迁入。

标题为“合并 TW 数据”，按钮为“暂不同步”和“开始同步”。开始后显示不可取消的本地进度并阻止前台操作；任务由应用级控制器持有，Activity 重建重新绑定。读取、合并、保存和完成按实际工作显示，提交前不显示成功，失败后可重试或关闭。

### 原子提交与重复保护

1. 本地读取、校验并准备合并计划，提交前原数据不变。
2. 在宿主真实 Room 的同一 SQLite 连接开启事务，重新核对选中源、来源快照及完成凭据，读取最新活动数据再合并。
3. 同一事务写入完整业务结果、当前源选择和完成凭据；任一步失败整批回滚，不替换数据库或来源快照文件。
4. 提交成功后结束旧会话，提示重新打开阅读器加载新数据；提交后的显示失败只提示重新打开，不重新累计。

完成凭据为目标源内的 `linovelib.migration.tw.v1.receipt`，通过实际 `LocalDataManager` 登记，随目标源切换、导出、清除和恢复。事务未提交时闪退保留原状态；提交后即使尚未显示完成，数据与凭据也一起生效。已有凭据时直接跳过，旧 TW 数据变化不作为新批次；不支持增量同步或逐书补迁。
