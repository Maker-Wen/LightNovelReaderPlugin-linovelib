## 目标与范围

重写 Linovelib 插件，补齐有实际使用价值的接口能力，改善发现、筛选和搜索体验。主要使用场景是在线阅读；用户当前没有发现正文阅读的明显问题，正文处理不作为本轮优化重点。

本轮严格只改插件。本体存在的能力缺口单独记录，不将本体修补纳入本轮交付。请求、网页解析和数据整理的内部写法可以重新选择，但应保留已确认的正常使用行为。

## 已确认的需求

### 兼容目标

- 首先面向 LightNovelReader 1.2.2 / API 3 开发。
- API 4 适配后续单独处理，不预设同一个插件包可以同时覆盖 API 3 和 API 4。
- 历史 API 3 宿主代码与当前 API 4 开发分支需要分别核对，不能直接用当前分支推断旧版能力。

### 插件设置与站点切换

- 使用已选定的 C 方案：普通设置行配原生开关，名称为“使用繁体站”。关闭使用简体站，开启使用繁体站。
- 设置页采用轻量布局，避免重卡片样式。
- 第一版切站允许重启后生效。设置变化后采用与本体一致风格的底部提示：“重启应用以生效”，操作为“重启”。由用户点击执行重启。
- 实现使用插件能够访问的公开能力与 Material 组件，不依赖本体内部界面类。

### 简繁互通

- 目标是共用书架和阅读进度。此前讨论的“分开书架”不再作为最终方向。
- 用户切换的是同一本书的站点版本，不应因此重新收藏或重新开始阅读。
- 正文缓存需要区分站点，避免旧站缓存误显示为当前站正文。采用站点章节 ID 和阅读记录键迁移，详见下文。
- 对应关系明确时，切换后恢复相同章节和大致阅读位置，不承诺定位到完全相同的一句话。
- 对应关系不明确时保留原记录，不按目录序号或相似标题直接覆盖进度；选择章节的具体交互需要结合本体已有能力确定。
- 本文的“互通”指简繁站之间的数据连续性，不包含跨设备云同步。

### 发现页与筛选

- 保留四个独立栏目：推荐、文库、排行、完结。
- 文库快捷筛选放在展开书单页面，不挤到发现首页搜索按钮旁。
- 从书单的更多入口进入展开列表，在标题下方展示横向筛选项，筛选项随列表滚动。
- 复用本体已有的筛选交互。展开页面不额外复制发现首页的栏目和搜索入口。
- 每个列表只展示该列表实际支持的条件。更换条件后重置分页，继续加载时保留条件。
- 文库支持地区、主题、排序、动画化状态、字数和写作状态六项原生单选筛选；排行榜等列表只沿用实际链接，不附加文库筛选。

### 正文与在线阅读

- 正文现有正常阅读逻辑作为回归基线，暂缓主动优化其分页拼接、文本整理和插图处理规则。
- 新请求或解析实现不应破坏正文、目录跳转和插图的正常显示。
- 离线下载、导出和卷封面扩展不作为本轮重点；已有功能仍需避免回归。

### 请求失败与重试

- 不因理论上的小概率异常扩大重写范围，目前没有失败频率数据支持将其列为重点功能。
- 在插件内部正确区分“请求失败”和“确实没有结果”，利用本体已支持的结果类型表达。
- 保留基本超时和有限重试，不增加复杂恢复流程或一组网络参数设置。
- API 3 无法展示的错误状态单独记为本体问题，不承诺仅靠插件补上原生重试按钮。

### 覆盖升级与旧数据

- 新版按直接覆盖升级交付，不要求用户先卸载旧版或重新建立书架。
- 保留书架、阅读进度和当前站点设置；升级不得将缺省站点选择覆盖到已有设置上。
- 保持已有身份与存储契约。若必须调整章节标识或配置存储，先证明旧记录能够兼容，再确定转换方式。
- 缓存的转换、失效或清理规则随简繁缓存方案确定，不使用“清空所有本地书本数据”代替正文缓存处理。
- 覆盖升级成立与否需要用实际旧发行包和新包验证，不能仅靠源码包名相同得出结论。

## 本轮接口补齐与体验改进

以下五项均已纳入本轮开发范围。

| 功能 | 预期改善 | 实现边界 |
| --- | --- | --- |
| 书单展开与筛选接入 | 从推荐、文库等列表继续查看更多，并使用有效筛选条件 | 提取真实更多链接；文库使用六项单选 |
| 搜索结果逐步展示 | 不等待所有书籍详情完成后才出现第一批结果 | 首批发出列表元数据，普通搜索原地补全详情 |

| 问题 | 对插件的影响 |
| --- | --- |
| 搜索错误页可以展示错误信息，但没有原生重试操作 | 插件可以改进错误文案；增加按钮涉及本体 |

这些缺口应单独留档，不为解决它们在插件中模拟一套本体页面。

## 数据兼容方案与验证边界

### API 3 下的简繁缓存与进度

API 3 中，正文缓存以章节 ID 为主键，阅读记录也按章节 ID 保存进度。仅给章节 ID 加站点前缀，会同时分开缓存和进度；直接共用章节 ID，则正文缓存可能互相覆盖。

使用 API 3 公开的本地书籍、书架和文本处理接口实现：

- 正文章节 ID 改为 `linovelib-v3:simplified:<编号>` / `linovelib-v3:traditional:<编号>`；网络请求还原数字编号，前后章链接与目录使用同一规则。图片目录也按站点区分。
- 保留数据源、书籍和卷 ID。启动时把已有阅读记录的章节键转换到当前站点，替换而不追加。最高进度冲突取最大值，当前阅读位置优先保留最近阅读章节的原记录，阅读时长和书本进度保持。
- 旧数字 ID、`linovelib-v2:`、未带站点的 `linovelib-v3:` 均可迁移；未知格式保留原值，不猜测章节对应。
- 启动准备已有阅读记录和书架书的本地目录；本地目录流经公开 TextProcessor 转换章节 ID。下载和导出直接请求数据源时也先准备本地回退目录。
- 不将经过宿主格式转换后的目录标题写回数据库，不改正文 JSON 或文本处理规则。
- 旧正文缓存没有可靠站点标识，不复制到新 ID，也不清空整个本地数据源。升级后的首次正文读取需联网重新获取。

API 3 的“清理孤立数据”只按当前目录判定章节归属，可能删除另一站缓存，切回后需要重新获取；这不影响书架或阅读记录。未加入书架且没有阅读记录的孤立旧缓存无法通过公开接口枚举，其缓存标记可能在打开目录前仍显示旧状态。

### 升级身份与发行包

本地插件源码的参考基线如下。这些值需要与用户实际使用的旧发行包核对，不直接套用更早的历史记录：

- 包名与设置文件名称：`io.nightfish.lightnovelreader.plugin.linovelib`。
- 站点设置键：`site`，当前保存枚举值 `SIMPLIFIED` / `TRADITIONAL`。
- 数据源 ID：由 `"linovelib".hashCode()` 生成。
- 基线章节前缀为 `linovelib-v3:`，新版使用带站点的前缀并通过公开接口迁移阅读记录键，保留旧数字编号。
- 插件注册、数据源身份、版本递增、签名与宿主安装方式，需要结合实际旧包完成覆盖验证。

API 3 宿主用 APK 包名识别插件，没有独立的 `@Plugin.id`。覆盖安装会检查 API 兼容性、整数版本和签名匹配；发布新版应保持包名及签名身份，并递增版本。数据源 ID 与书籍、章节标识还需分别保持兼容，不能仅凭包名不变推断旧数据能够保留。

相关源码位于 `LinovelibPlugin.kt`、`LinovelibDataSourceConfiguration.kt`、`LinovelibChapterIds.kt`、`LinovelibWebDataSource.kt` 和 `plugin/build.gradle.kts`。

## 验收重点

1. 用实际旧版本数据覆盖升级，确认书架、阅读进度和站点设置保留，重启后仍可读取。
2. 简体切繁体再切回：同一本书不重复收藏，已对应章节能续读，进度不会错误累计或被覆盖。
3. 有旧正文缓存和没有缓存时分别切站，确认不会误显示另一站正文。
4. 四个发现栏目、更多入口、筛选切换和继续加载行为符合已确认布局及条件规则。
5. 请求失败与真实空结果在插件层可区分，本体能够表达的场景显示正确；本体限制明确记录。
6. 搜索验证结果完整性、首批显示与详情补全；展开列表验证网站分页，搜索不假定有宿主加载更多入口。
7. 现有正文、插图和目录前后章跳转通过阅读回归。

编译、静态检查或单元测试通过不等于覆盖升级和设备阅读验收通过。包验证与运行验证分别记录。
