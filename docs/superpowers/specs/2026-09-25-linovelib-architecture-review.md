# Linovelib 架构设计审查记录

日期：2026-09-25。

审查对象：[架构整理设计](2026-09-25-linovelib-architecture-design.md)，以及插件当前工作区与 API 3 宿主 `6ea57a9` 的实际调用契约。审查对象是拟实施的设计，不是已经实现的重构。

## 1. 结论

两席独立只读审查共提出 3 项 P2 设计问题，无 P1。三项均已修订，原审查席逐项复核通过；复核范围内没有剩余 P1／P2 设计阻塞，可以进入实施规划。

生产代码尚未应用这些修订，因此已有分页和离线状态问题不能标记为已修复。

## 3. 发现与处理

| 编号 | 严重度 | 初稿问题 | 已采用修订 | 复核 |
| --- | --- | --- | --- | --- |
| AR-01 | P2 | 仅保留 volatile 通道身份比较不能保证原子性；旧任务可清空新通道，也可能取消后迟到发布 | 同一短锁保护发布、锁内 ensureActive、身份比较及清理；loadMore 只在锁内取引用，发送与阻塞操作在锁外 | 关闭；设计 §4.3／§8 |
| AR-02 | P2 | 离线状态允许在请求 slot 外发布，旧探测失败可能覆盖较新的在线结果 | 成功请求和主动检查最终失败在各自既有 slot 释放前发布；移除 WebDataSource／onLoad 的重复赋值；补两种执行顺序的交错检查 | 关闭；设计 §5.2／§8 |
| AR-03 | P2 | 仅注入 HttpClient 根 URL 无法直接测试 WebDataSource 中 private、固定 HOST 的正文分页循环 | 将原循环改为同文件 internal 顶层函数，生产与本地服务测试共用；注入 loadPage／host，不新建正文加载类或改变算法 | 关闭；设计 §8 |

另有两项非阻塞澄清已纳入设计：

- 插件保证取消后不继续发出结果；宿主先 clear 后 cancel、旧 emission 已进入同步 collector 的追加竞态，仍属于 API 3 宿主边界，不能承诺本轮全部消除。
- MetadataStore 按最近写入淘汰，更新旧键必须移到末尾；不能把 LinkedHashMap 默认的首次插入顺序误当成最近写入顺序。验收增加“重写旧键后淘汰”。

## 4. 已验证的设计前提

- API 3 宿主每个返回栈 ViewModel 初始化时只取得一次展开页数据源，后续筛选与 loadMore 都使用该实例。普通 Map 快照能隔离页面状态。
- 实际 `io.nightfish.lightnovelreader:api:0.3` 的父类 Map getter 非 final，接口／父类／子类 JVM 描述符一致。最小 Kotlin probe 编译并经接口调用通过，独立审查席再次执行通过。
- probe 同时确认继承的 expanded 登记方法会写入临时快照，因此设计明确禁止继续使用该登记路径。
- Filter 对象包含可变值及宿主监听器，必须每页面新建完整筛选器；复制 List 不足以隔离。
- 定义表保存不可变标题与目标，不持有页面实例；网络请求和分页协程不会由 Map getter 启动。

ABI 最小实验位置：`/private/tmp/lnr-api3-map-abi-20260925/FreshMapProvider.kt`、`probe.jar`、`abstract.javap.txt`。输出为 `PASS: interface dispatch, fresh maps, fresh sources, discarded registration`。

先前结构评估的双 collector 失败探针位于 `/private/tmp/linovelib-structure-probe/`。它证明现有共享实例的问题，不能当作新实例方案已经完成行为验收。

## 5. 已明确保留的边界

| 边界 | 原因与处理 |
| --- | --- |
| Map getter 每次构造全部登记页面的轻量实例 | 采用普通 Map 的 O(N) 成本；无 I/O，重复点击不增加定义；有实际测量后再考虑宿主工厂接口 |
| 动态页面进程重建 | 现有路由只有 ID，定义在内存；完整恢复需额外设计，不声称本轮修复 |
| 展开页下拉刷新与错误显示 | API 3 宿主限制，插件不模拟新 UI |
| 辅助元数据淘汰 | 每类 256 项，不新增 TTL；淘汰后使用摘要／关键词等既有回退，不改持久化数据 |
| 图片失败恢复与磁盘回收 | 保留现有图片规则，另立需求，避免把正文行为变更混入架构整理 |
